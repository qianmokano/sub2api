# 用户维护页与北京时间 04:00 预约升级

## 结论与依据

- 预约由独立主机服务保存和执行，继续使用原 SQLite、互斥锁、固定镜像清单和完整恢复流程。等待预约不属于应用启动协调器的维护状态；旧 `/jobs/current` 过滤新增状态。
- 单个未完成任务占用全局升级名额。准备在线完成；开始维护前再次核对来源版本、清单、磁盘、健康及北京时间 04:00 的一分钟窗口。重启时过期预约直接错过，不补跑。
- Nginx 独立提供维护 HTML；公开状态仅含时间和概况。浏览器导航显示说明，API 和流式调用维持 JSON 503。私有进度凭据延长到预约后 24 小时。
- 已查阅现有任务存储、控制接口、执行器、安装接线、CLI 与测试模式。现场核对生产运行 v0.2.16-6，完整恢复和数据验收仍保留。

## 实施与验收

1. 主机协议、持久预约、在线准备、竞争控制与截止窗口测试。
2. 独立维护页、Nginx 接线、管理员 API、预约入口和全站横幅。
3. 单元/竞态覆盖率、真实 Docker/Nginx/HTTPS 浏览器、完整 CI 和生产构建。
4. PR、main 验证、新固定标签及双架构发布；先替换主机服务，再通过 CLI 预约下一次北京时间 04:00，提前发布一次公告。禁止立即维护或每日自动升级。

发布和上线结果另记 RELEASE 文件；本记录不保存凭据。

首次完整 CI 的 HTTPS 浏览器验收发现维护页 CSP 哈希前缀使用了冒号，浏览器阻止脚本执行。已改为标准 `sha256-` 前缀；原验收继续检查真实浏览器中的开始时间、计时和恢复刷新。预约 POST 的响应捕获同时排除轮询 GET，避免覆盖创建结果。
