# fork 后台在线升级

## 目标与基线

管理员在现有版本菜单检查并安装 qianmokano/sub2api 的正式版本。每次升级保留完整备份、实际隔离恢复、迁移和数据验收。线上基线为 v0.2.16-1；现有账号、通行证、业务数据和运行凭据必须保持。首版不提供定时升级和上线后的任意版本回退。

## 依据与设计

- 当前更新器固定下载上游二进制，kano-container 有主动拒绝保护；fork 需要独立容器升级分支，不解除上游下载保护。
- 当前后台操作锁存放在 PostgreSQL，HTTP 操作虽脱离请求上下文，仍随应用退出结束；升级任务必须在主机独立运行、独立持久化和互斥。
- 发布流程已有固定版本双架构镜像和镜像摘要，尚无机器可读的更新清单或独立执行服务安装包。
- 现有完整备份与恢复脚本已验证全部真实挂载、PostgreSQL 18 逻辑恢复、Redis 值及绝对有效期、旧字段完整指纹和隔离副作用边界。本次将其原则实现为可复用 Go 服务，取消每版硬编码。
- 现有数据管理服务已经弃用，不能作为升级执行器。

采用主机 Go/systemd 服务、文件锁和独立 SQLite；应用通过受限 Unix socket 提交已验证的固定版本任务。Nginx 提供独立进度页和只读任务状态，任务凭据只经 HttpOnly Cookie 传递。维护前拉取并校验镜像，维护后完整备份及隔离恢复，验证后才切换并开放业务流量。失败恢复严格止于开放新业务写入之前。

## 验证与下一步

当前实现已有共享协议与受限 Unix 客户端、独立主机执行包、SQLite 任务/操作者/步骤/恢复检查点、完整冷备与逻辑恢复、旧字段和 Redis 绝对有效期比较、失败恢复及开放流量后的恢复边界。主机执行器与应用导入依赖分离，原版二进制更新分支保留。后台 HTTP 202 接口、幂等键、受限进度 Cookie、版本菜单和最近任务恢复已接通；安装器增量修改 Nginx 并验证，失败时恢复原站点配置。维护标志位于持久目录，主机重启后仍有效。

已通过相关 Go 单元/竞态测试、既有 service/admin 单元测试、升级面板与版本标记测试、前端类型检查和构建。故障单测覆盖镜像/磁盘/逻辑备份/恢复/Redis/迁移/生产切换/数据检查失败、备份损坏、过程被中断后恢复及开放流量后保留新写入。最终覆盖范围包含共享协议、主机执行包及命令入口，本地合并普通用户竞态测试与 Linux root 生命周期单测后的语句覆盖率为 80.8%。命令入口测试验证非 root 拒绝、服务启动和取消后的锁/套接字释放、既有任务阻止重新安装、损坏恢复状态拒绝，以及命令输出不包含进度凭据。CI 分别以普通用户和 root 运行竞态测试并合并覆盖；root 使用独立编译缓存且禁用测试结果缓存，避免复用普通用户跳过的测试结果。

真实 Docker 已验证完整升级、磁盘不足、备份损坏、逻辑恢复失败、迁移破坏旧数据、新版健康失败及执行进程强制退出后恢复七个场景，每个场景完整比较 101 张原表、384 行数据，覆盖身份绑定、订单、订阅、自定义字段、通行证与初始权益设置及升级前管理员会话。成功升级后重新启动执行服务，确认开放流量后的新余额写入不会被旧数据覆盖。

真实 HTTPS Chromium 点击升级验收也已全部通过：应用返回 HTTP 202，短期 Cookie 为单任务、Secure、HttpOnly、SameSite Strict，页面脚本不能读取凭据，匿名访问页面及状态接口均为 403。维护时应用健康返回 503，独立进度页刷新和状态查询仍为 200；完成后原管理员 JWT 仍可用，新版显示及最近任务入口正常。独立复核完整比较 101 张原表、388 行停写数据，并再次校验原备份文件。浏览器正常登录和声明确认在点击前完成；点击后既有审计中间件新增一条 HTTP 202 记录，测试明确验证该记录，并完整比较停写快照中的全部审计历史，没有放宽生产字段校验。

完整 Go 单元和集成回归已在 PR CI 通过；本机出现的两项既有计费内存和模型缓存断言失败，定向各重跑三次也均通过。前端 629 项测试通过，升级面板语句覆盖率 99.13%、分支 89.09%、函数 100%；新后台服务和接口覆盖率分别为 100% 和 83.9%。本机只有 8 GB 内存，真实矩阵与大型编译改为分开运行，CI 使用独立 Linux 任务执行真实 Docker/Chromium 和覆盖率门槛。迁移故障矩阵使用实际上一已发布镜像，浏览器场景另行提供带本次界面的 v1 测试镜像。发布和生产安装尚未完成。

首轮 CI 暴露了测试卷名导致 Unix socket 超出长度限制，已缩短名称并增加长度预检；lint 修正限定在受信主机命令边界、解析器和错误文本，完整 CI lint 已通过。HTTPS 测试转发层增加短期地址缓存，避免每个前端资源重复启动 Docker CLI；测试账号通过既有管理员声明确认并初始化新手引导状态后再检查版本。测试在交付实际 HTTP 202 响应给页面前读取正文，避免立即导航让 Chromium 丢弃正文。最终提交仍需新一轮完整 CI 验证。

只读 VPS 检查确认原镜像为 v0.2.16-1，PostgreSQL 18、Redis 8 及 Nginx 健康，数据共有四个真实挂载（包括 PostgreSQL 18 的匿名父卷），可用空间约 8.0 GB。生产尚未修改。SSH 的非默认端口连接使用现有已验证主机密钥完成核对。
